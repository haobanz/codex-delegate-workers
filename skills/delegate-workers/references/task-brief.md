# 明确任务书与分节委派

主代理负责整理事实、整体方案、共享接口和最终验收。子代理按清楚的小节采集
信息或执行，不替主代理重新规划整个任务。原生、统一 MCP 和独立 CLI 使用同一
流程；模型与思考强度仍按用户或项目选择，不因为“专注执行”而自动降低强度。

## 工作流程

1. **列信息缺口。** 主代理明确方案需要的事实，按文件、接口或问题划定只读
   采集范围。采集 worker 返回事实、出处/文件位置、覆盖情况和未知项，不顺手
   实现。已有足够可靠的信息时跳过重复采集。
2. **整理并定方案。** 主代理汇总、交叉核对采集结果，决定修改方式和共享契约，
   明确本任务相关的字段、类型、单位、默认值和错误语义，按实际需要说明。
   未确定的接口或事实不能包装成已核实结论交给执行者猜测。
3. **拆小节并派发。** 默认按单一目标、可独立验证的交付拆分较大任务。主代理
   先确定公共接口；无待交付依赖且写入范围不重叠的小节可并行，有依赖的小节
   等待前置结果通过主代理审查。模块存在调用关系，但契约已确定且双方不等待
   对方实现时也可并行；不同文件不等于契约独立，契约变化要重评受影响小节。
   单一明确的小任务不用人为再拆，也不设固定并发数。
4. **执行并自测。** worker 只做任务书所需的定位、实现和验证，不重做全局规划，
   不额外调查、重构、增加功能或自行递归派发。主代理明确授权该小节继续分工时
   才能再委派。保留完成具体任务必要的局部判断。
5. **主代理审查。** 查看真实 diff 和相关测试，检查边界、共享契约、整体目标
   以及相关整体调用/配置链或适用集成路径；接受结果或下发具体修正小节，
   写明位置、问题、预期修正和复验方式。派发成功、
   worker 自测完成和主代理验收通过分别报告。

遇到事实冲突、不合理方案、缺失信息、接口不一致或需要越界修改，worker 可以
反驳：提交证据、影响和最小修正建议，暂停受影响部分，只继续已明确不受影响的
授权独立小节。不擅改共享契约或扩大范围，也不把普通必要定位当成重新开展全局
调查。主代理按真实工具确认验证命令和预期；未核实的标为待确认，不编造已运行
的检查或保证成功。

## 可复制任务书

下面结构可直接写在派发消息中，按实际任务简化；不强制创建文件、使用固定
JSON/字段校验或增加用户配置。路径、已核实结论和验证命令须由主代理确认后填写。

```text
角色：只读信息采集 / 执行（二选一）。
小节与完成条件：一个明确目标；写明可检查的交付及预期行为。
已核实信息：相关事实、出处/文件位置、主代理已决定的接口与方案。
边界：项目绝对路径；允许读取范围；允许修改的具体文件与函数；临时目录。
步骤与保留行为：具体修改顺序、必须保持的接口/行为；采集任务列要回答的问题。
依赖与并发：前置结果及是否已验收；能与哪些独立小节并行；共享文件的写入归属。
验证：主代理按真实工具确认的命令或操作及预期；未核实的标为待确认。
回报：完成情况、事实与来源/改动位置、覆盖情况、验证及结果、异议和未知项。
异常：带证据说明冲突、影响及最小建议，暂停受影响部分，只继续明确不受影响
的授权独立小节，不擅自扩范围或改契约；契约变化由主代理重评相关小节。
执行约束：只做本小节必要的定位、实现和自测，不重做整体规划、不额外发散，
不自行再委派；主代理另有明确分工授权时除外。
```

以下以本仓库的模型预检为例展示消息写法；这不是要求自动执行的任务。主代理
应先核对文件、现有覆盖及实际验证工具，已有同等测试时不要重复增加。

```text
角色：只读信息采集。
目标：确认 resolve() 对显式未知模型的处理及测试覆盖，为主代理决定是否补测。
读取：skills/delegate-workers/scripts/workers.py 中 resolve()、validate_worker()，
以及 tests/test_workers.py 的 WorkerTests；只做与这两个问题有关的定位，不改文件。
问题：未知模型是否原样保留？compatibility.status 与 runtime_verified 是什么？
已有哪项测试覆盖显式覆盖，是否检查输入配置保持不变？
回报：逐项给事实、文件/函数/测试位置、已检查范围和未知项，不提供顺带实现。
并发：可与只读安装入口采集并行。临时内容放到主代理给定的项目 tmp/ 子目录。
```

```text
角色：执行；小节：补充未知模型显式覆盖的回归检查。
完成条件：若现有测试缺少该断言，补齐未知 ID 原样保留、静态状态 unverified、
runtime_verified 为 false、输入配置不变的检查；已有覆盖则报告位置，不重复增加。
已核实：workers.py 的 resolve()/validate_worker() 负责静态预检；来源是主代理已
审阅的源码及采集回报。未知模型的处理契约保持不变，不发起真实供应商请求。
读取：skills/delegate-workers/scripts/workers.py 和 tests/test_workers.py。
只可修改：tests/test_workers.py 的 WorkerTests 相关用例；不改生产代码或配置。
步骤：核对现有用例；在缺少断言的用例中补充断言；运行相关测试并报告结果。
依赖与并发：信息采集已由主代理验收；可以与 README 独立文档小节并行，
本轮其他 worker 不写 tests/test_workers.py。
验证：python3 -m unittest discover -s tests -p test_workers.py，预期相关用例通过；
命令未获主代理当前环境确认时标为待确认。主代理还检查预检结果的相关调用链。
回报：修改的测试、已有覆盖位置、测试命令及结果、异议和未验证项。
异常：若实现与已定契约冲突，带源码/失败测试证据上报，暂停该断言的实现，
不自行修改 workers.py 或调整模型。临时内容只放主代理给定的项目 tmp/ 子目录。
只做本小节必要定位、补测和自测，不重新设计预检、不自行再委派。
```
